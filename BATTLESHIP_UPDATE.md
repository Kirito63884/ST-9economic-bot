# Морской бой на двоих

**Игры → Морской бой**, `/games/battleship/lobby`.
Есть открытые столы и приглашения, ручная/случайная расстановка, готовность,
равные взносы, полный банк победителю и повторный бой.
[Памятка игрока](docs/BATTLESHIP_PLAYER_GUIDE.md).

## Правила

Два поля 10×10. У каждого десять прямых кораблей: 4, 3, 3, 2, 2, 2, 1, 1, 1, 1.
Они не пересекаются и не касаются сторонами или углами. Сервер проверяет
размеры, непрерывность, положение и двадцать уникальных палуб.

Состав флота, запрет соприкосновения и дополнительный выстрел после попадания
сверены с [опубликованным описанием классических правил](https://github.com/grinat/sea-battle#правила).
Код и изображения этой реализации не заимствованы. Условия ставок и таймеров
относятся к сайту ST-9 и явно показаны в интерфейсе.

После сохранения флотов оба подтверждают готовность, создатель запускает бой.
Первого стрелка случайно выбирает сервер. Попадание/потопление сохраняет ход,
промах передаёт его сопернику. Повторно стрелять в известную клетку нельзя.
Вода вокруг потопленного корабля отмечается автоматически.
Побеждает первый, потопивший весь чужой флот. Корабли и их типы видит только владелец своего поля, в том числе после боя.

Таймер: 45/60/90/120 секунд. Тайм-аут передаёт ход без выстрела; три своих
тайм-аута подряд — сдача. Ручной выстрел сбрасывает счётчик. Закрытие вкладки
само по себе не считается немедленной сдачей.

## Взносы

Взнос одинаковый для обоих; 0 БК — бесплатная игра. Максимум — меньший текущий
баланс **участников стола**, остальные аккаунты сайта не влияют. При отрицательном
балансе участие недоступно. Пока в комнате только создатель, предел — его баланс.

Соперник с меньшим неотрицательным балансом может войти для согласования суммы.
Новый предел виден в комнате. Создатель снижает взнос в «Условиях стола»;
изменение условий сбрасывает готовность обоих. Превышение предела блокирует
готовность/запуск без списаний. Перед запуском в той же транзакции повторно
проверяются профили, кошельки, готовность, расстановки и место для выигрыша.

Списываются ровно два взноса при запуске. Зафиксированная ставка не пересчитывается
после списания: нулевой остаток не отменяет оплаченный бой. Победитель получает
`2 × взнос` без комиссии. История БК хранит чистый результат: `+взнос` победителю,
`−взнос` проигравшему. Бесплатный бой сохраняет результат с нулевой суммой.
Выход во время боя — сдача и весь банк сопернику; до старта — освобождение места.

## Интерфейс и сохранение

Корабли ставятся выбором размера, направления и начальной клетки. Нажатие на свой
корабль удаляет его. Ручной черновик сохраняется отдельной кнопкой; авторасстановка
сразу сохраняет полный флот. Опрос и действия соперника не стирают черновик,
но перезагрузка стирает несохранённые правки. Сохранённые поля и бой восстанавливаются.

Выстрел — одно нажатие на клетку противника, без отдельного подтверждения.
Прокрутка, долгое касание, масштабирование двумя пальцами и отменённый жест не
стреляют. На телефоне вкладки переключают собственное поле и поле соперника.
Потеря связи, устаревшее состояние и таймер блокируют действия. Выстрелы и деньги
автоматически не повторяются; фиксированная готовность может повториться один раз
после конфликта версии. Неизвестный чужой флот API не возвращает даже главному
администратору, в том числе после окончания партии. Соперник видит лишь метки
выстрелов, а не модели, массивы кораблей, типы или счётчики оставшихся палуб.

Стол закрывается через 8 часов без успешных POST-действий участника. Опросы
и таймеры срок не продлевают. Незавершённые взносы возвращаются один раз,
завершённые результаты сохраняют выплаты. Повреждённый банк или невозможный
возврат/выигрыш сохраняют стол для исправления. Последний выстрел при неуспешной
выплате откатывается вместе с кошельком и историей. Архивация вызывает штатную
сдачу. После простоя приложения игровые часы восстанавливаются, срок неактивности
не сдвигается. Повторный бой очищает поля и требует новой готовности.

## Устройство и проверка

`battleship.py` — правила/геометрия/таймеры, `battleship_routes.py` — API и кошелёк.
`templates/_battleship_*`, `battleship_lobby.html`, `battleship_table.html` —
читаемый CSS/JS и поля без внешнего игрового движка. Собственные SVG-модели
линкора, крейсеров, эсминцев и катеров имеют башни, надстройки и отдельные силуэты.
`_battleship_ships.js.html` рисует только собственный флот,
`_battleship_input.js.html` распознаёт намеренное нажатие и отменяет жесты прокрутки. Новых таблиц или зависимостей
нет. Runtime хранит ключ `battleship`; старые снимки без него читаются как прежде.
Общие сервисы подключаются необязательным `battleship=None`.

Поддержаны каталог, навигация, любимая игра, история БК, журнал, активность,
административное управление столами и выход архивируемого пользователя.
При объединении с другими новыми играми сохраните обе интеграции в общих файлах.

Общие проверки: `bash scripts/check.sh`. Новые сценарии — `tests/test_battleship.py`.
Браузерная проверка:

```bash
python scripts/check_battleship_browser.py --app-python .venv/bin/python
```

Запускающему Python нужен Playwright и установленный Chromium (`--chromium`).
`--screenshot-dir /tmp/battleship-screens` сохраняет снимки, необязательный
`--bootstrap-css` принимает локальный Bootstrap. Иначе для теста используется
минимальный CSS. Внешние запросы браузера блокируются. Runner создаёт временную
SQLite-базу, вымышленных игроков и loopback-сервер, не читает `.env`, не запускает
фоновые интеграции и убирает сервер/данные после проверки.

## Установка

После ревью выберите полный SHA из согласованного `main`:

```bash
bash scripts/update_battleship_game.sh FULL_COMMIT_SHA /var/www/balance-app
```

Запуск от root. Сначала проверяются исходники и наличие зависимых модулей.
Приватная копия выбранных файлов и согласованная SQLite-копия с `quick_check`
попадают в `/root/battleship-game-before-*`. Если коммит не сохраняет ключи уже
установленных игр в runtime, обновление остановится до замены. Используйте SHA
после объединения нужных PR; зависимые модули других игр должны быть установлены.

Копируются только перечисленные файлы. `.env`, рабочая база, venv и данные
источников не заменяются. Проверяется импорт `main` без запуска lifespan.
Обычно перезапускается только сайт; бот — дополнительно при отличии предыдущей
политики сборов. SQSTAT и игровой монитор не перезапускаются.
При ошибке копирования/импорта/HTTP восстанавливаются прежние файлы, новые удаляются.
Рабочая БД поверх записей других процессов автоматически не восстанавливается.
После установки: Ctrl+F5 → Игры → Морской бой, бесплатная партия с двух аккаунтов,
проверка расстановки, попадания/промаха, сдачи и истории.
