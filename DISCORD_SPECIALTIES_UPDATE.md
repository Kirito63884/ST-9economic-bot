# Кнопки учётных специальностей

`discord_specialties.py` добавляет панель в канал `1448264624242819093` существующего сервера `REQUIRED_GUILD_ID`. Работает внутри `discord-bot.service` с прежним `DISCORD_BOT_TOKEN`. Отдельный бот и новый токен не нужны.

Кнопки: Стрелок, Медик, Пулемётчик, Гренадер, Гранатомётчик, Сапёр, Марксман, Механик, Пилот. Можно выбрать несколько; повторное нажатие снимает только выбранную роль. Изменение идёт через атомарный Discord endpoint одной роли: группы, награды и другие роли участника сохраняются. Ответ виден только нажавшему. Фактическое назначение на должность остаётся решением командования.

## Перед установкой

В Discord откройте **Настройки сервера → Роли**. У роли существующего бота включите **Управлять ролями** и расположите её выше всех девяти ролей специальностей. Право «Администратор» не требуется.

В канале специальностей бот должен иметь **Просматривать канал**, **Отправлять сообщения**, **Встраивать ссылки** и **Читать историю сообщений**. У выдаваемых специальностей не должно быть административных/модераторских полномочий. `@everyone`, управляемые интеграцией роли и `REQUIRED_ROLE_ID` выдавать через эту панель нельзя.

## Установка

Установщик принимает полный SHA коммита:

```bash
bash /путь/к/update_discord_specialties.sh FULL_COMMIT_SHA /var/www/balance-app
```

Он скачивает закреплённую версию, проверяет синтаксис до остановки бота, создаёт приватный архив прежних файлов в `/root/discord-specialties-before-*.tar.gz` и меняет только `discord_bot.py` и `discord_specialties.py`. Перезапускается только `discord-bot.service`; сборщик SQSTAT продолжает текущий цикл. `.env`, база и окружение Python не перезаписываются. При ошибке копирования, компиляции или запуска прежние файлы восстанавливаются автоматически. Ошибка публикации в Discord отражается в журнале, повторная попытка — через пять минут.

## Поиск существующих ролей

При первом запуске бот ищет ровно одну существующую роль для каждой специальности по полному названию. Значки, пробелы, регистр, различие `е/ё` игнорируются. Например, `✥ Стрелок` подходит; `Лучший стрелок` не подходит. Роли не создаются.

Если какой-то роли нет или одинаковых названий несколько, панель не публикуется. Уточните названия либо задайте явную карту в `.env` (значения ниже — примеры, замените настоящими ID):

```dotenv
DISCORD_SPECIALTY_ROLE_IDS='{"rifleman":"100000000000000001","medic":"100000000000000002","machine_gunner":"100000000000000003","grenadier":"100000000000000004","anti_tank":"100000000000000005","sapper":"100000000000000006","marksman":"100000000000000007","mechanic":"100000000000000008","pilot":"100000000000000009"}'
```

Параметр необязателен; без него используется автоматический поиск. Указывайте все девять разных ID. Для копирования ID включите в Discord **Настройки пользователя → Расширенные → Режим разработчика**, затем правой кнопкой по роли → **Копировать ID**. После изменения конфигурации перезапустите только `discord-bot.service`.

Найденные ID ролей и ID сообщения сохраняются в существующей таблице `automation_settings`, отдельно для этого бота и канала. Поэтому последующее переименование роли и перезапуск бота не ломают кнопки. Если роль удалена, выдача блокируется: её замену нужно явно указать в карте. После обрыва между отправкой сообщения и сохранением ID панель восстанавливается из истории по автору и маркеру. Если сообщение удалено, бот восстановит его после переподключения/перезапуска. Чужие сообщения, включая ProBot, бот не редактирует и не удаляет.

## Проверка

```bash
systemctl is-active discord-bot.service
journalctl -u discord-bot.service --since '3 minutes ago' --no-pager -n 70
```

`active` означает только работающий процесс. Публикацию подтверждают строка `Specialty panel ready` и новая панель в указанном канале. Проверьте выдачу двух разных специальностей, снятие одной повторным нажатием и сохранение другой. После `systemctl restart discord-bot.service` кнопки должны работать в том же сообщении без создания дубля.

Старые кнопки ProBot запустить от другого бота нельзя. Старое сообщение можно вручную удалить после проверки новой панели; установщик его сохраняет.

## Безопасность и проверка кода

Обработчик проверяет сервер, канал, точный ID действующего сообщения и его автора; разрешены только девять фиксированных ключей. Перед каждым изменением заново получает участника, бота и роли из Discord, проверяет полномочия роли, иерархию и доступ участника к каналу. Изменения сериализованы; полный список ролей не перезаписывается. В журнале фиксируются только ID участника/роли и результат; секреты и токены не выводятся.

Локальные тесты используют поддельный Discord, без публикации реальных сообщений. Они проверяют выдачу/снятие, сохранение остальных ролей, перезапуск, восстановление после обрыва, отсутствие дублей и блокировку поддельных сообщений/привилегированных ролей. Настоящие названия ролей и права нужно проверить на рабочем сервере.
