# Дополнительный вход через Discord-бота

Этот архив устанавливается поверх уже исправленной версии в `/var/www/balance-app`. `.env`, `app.db` и `venv` в архив не включены. Библиотеки не изменились, переустановка зависимостей не нужна. Обновить нужно весь архив, включая `login_links.py`, общую схему БД, бота и шаблоны.

## Как пользоваться

- Игрок вводит `/login` в Discord на телефоне, на вашем сервере. Ответ со ссылкой виден только ему. Ссылку можно открыть на телефоне либо скопировать на компьютер.
- Страница просит нажать «Войти в мой профиль». Сам просмотр/предпросмотр ссылки не выполняет вход.
- Ссылка действует 10 минут и используется один раз. При выдаче новой прежняя отменяется. Между выдачами одному игроку нужно 30 секунд.
- Открывается тот же профиль: Discord ID, ник, баланс, Steam ID, права, приватность, история и игры сохраняются. Сайт заново проверяет роль через Discord-бота.
- Главный администратор может нажать 🔑 в строке игрока или ввести Discord ID в блоке «Вход без Discord в браузере». Для нового участника профиль создаётся при первом успешном входе. Самостоятельного назначения прав нет.
- В этом же блоке кнопка «Отменить ссылки» отзывает неиспользованные ссылки указанного Discord ID. Она не закрывает уже созданные сессии.
- Получить Discord ID можно в приложении Discord: включить режим разработчика в настройках → открыть профиль участника → «Копировать ID». Нужен ID пользователя, а не сервера или роли.
- При утрате роли доступ по ссылке запрещён. Фоновая проверка отзывает ссылки и архивирует профиль по прежним правилам на семь дней.

Ссылку можно переслать вместе с полным адресом и частью после `#`. Не публикуйте её в общем канале. Выдавая ссылку вручную, убедитесь, что получатель — владелец выбранного Discord-профиля.

## 2. Остановка и новая резервная копия

Дальше команды выполняются в SSH. Сохраняйте это SSH-соединение до завершения обновления, чтобы переменная `backup_dir` оставалась доступна. При ошибке остановитесь, не переходите к следующему шагу.

```bash
systemctl stop balance-app.service discord-bot.service
backup_dir="/root/balance-app-before-login-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$backup_dir"
tar --exclude=venv --exclude=__pycache__ -czf "$backup_dir/app.tar.gz" -C /var/www balance-app
ls -lh "$backup_dir/app.tar.gz"
```

Для текущей исправленной версии игры уже сохраняются в БД. Короткая остановка для обновления приостанавливает их по прежним правилам.

## 3. Распаковка и настройка адреса сайта

```bash
python3 -m zipfile -e /tmp/discord-app-login.zip /var/www/balance-app
cd /var/www/balance-app
```

Добавьте публичный HTTPS-адрес в существующий `.env`. Этот скрипт меняет только `SITE_URL`, не выводит секреты и сохраняет владельца и права существующего файла:

```bash
venv/bin/python - <<'PY'
from pathlib import Path
import re
path = Path(".env")
config = path.read_text(encoding="utf-8")
line = "SITE_URL=https://striketeam9bank.ru"
updated, count = re.subn(r"(?m)^[ \t]*(?:export[ \t]+)?SITE_URL[ \t]*=.*$", line, config)
if not count:
    updated = config.rstrip("\n") + "\n" + line + "\n"
path.write_text(updated, encoding="utf-8")
PY
```

Если `SITE_URL` не задан, код берёт адрес из `DISCORD_REDIRECT_URI`. Для публичных ссылок требуется HTTPS; HTTP допускается только для локальной разработки.

## 4. Проверка и миграция

```bash
venv/bin/python -m compileall -q main.py discord_bot.py database.py runtime.py login_links.py migrate.py
venv/bin/python migrate.py
venv/bin/python -c "from login_links import site_origin; print(site_origin())"
```

Ожидаются «Миграция завершена. Пользователи и балансы сохранены.» и `https://striketeam9bank.ru`. Миграция создаёт таблицу `login_links`; пользователи и балансы не заменяются.

## 5. Запуск и проверка

```bash
systemctl start balance-app.service discord-bot.service
systemctl status balance-app.service discord-bot.service --no-pager -l
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/
journalctl -u balance-app.service -u discord-bot.service -n 60 --no-pager
```

Обе службы должны быть `active (running)`, сайт отвечать `200`. Бот должен синхронизировать 11 slash-команд, включая `/login`. Если новая команда ещё не отображается, переоткройте приложение Discord и проверьте журнал синхронизации.

1. В Discord на телефоне введите `/login` на вашем сервере.
2. Скопируйте всю ссылку на компьютер. Можно проверить в отдельном приватном окне браузера без авторизации Discord.
3. Откройте её и нажмите «Войти в мой профиль»; проверьте прежний баланс и ник.
4. Откройте эту же ссылку в другом приватном окне: повторный вход должен быть запрещён. Завершённый вход в первом окне при этом сохраняется.
5. Под главным администратором проверьте выдачу ссылки через 🔑 и отмену ссылки. Для отмены используйте новую, ещё не использованную ссылку.
6. Ссылки и их срок действия сохраняются при перезапуске; срок в 10 минут при этом продолжает идти.

## Откат при ошибке установки

В том же SSH-сеансе:

```bash
systemctl stop balance-app.service discord-bot.service
tar -xzf "$backup_dir/app.tar.gz" -C /var/www
systemctl start balance-app.service discord-bot.service
```

Библиотеки не менялись, поэтому восстанавливать их не нужно. Откат возвращает код, `.env` и базу на момент резервной копии. Если после обновления уже были новые игры или изменения балансов, они также будут возвращены к этому моменту; в этом случае сначала разберите ошибку, прежде чем восстанавливать базу.

## Проверки до установки

92 автоматических теста прошли на Python 3.12 с SQLite. Проверены: старые игры/выплаты, сохранение профиля при новом входе, одноразовость, истечение срока, отзыв, защита от подмены роли и CSRF, ограничения выдачи, приватный ответ бота, параллельное использование и вход в отдельном процессе. Проверены 11 страниц и синтаксис 12 встроенных блоков JavaScript. Реальное подключение новой команды к вашему Discord проверяется после установки.

В базе хранится только SHA-256-отпечаток секрета ссылки. Сам секрет находится в части URL после `#`, которая не передаётся серверу при GET и не попадает в обычные HTTP-журналы. Страница входа не загружает внешние ресурсы и запрещает передачу Referer; вход выполняется отдельным POST после подтверждения.
