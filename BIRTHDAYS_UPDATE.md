# Поздравления с днём рождения

Бот поздравляет участников сервера в канале `1546906175751192706` в 07:00
Europe/Moscow. Розовый embed содержит упоминание именинника, дату рождения,
возраст, пожелания и аватар. После публикации бот добавляет 👍 и создаёт ветку
поздравлений, если у него есть соответствующие права. Упоминается только именинник.

Если бот запущен позже 07:00, поздравление отправляется в течение минуты того же
дня. За прошедшие дни рассылки нет. Дата 29 февраля в невисокосный год отмечается
1 марта. Даты вышедших участников остаются в реестре; пока участника нет на сервере,
поздравление не отправляется. После возвращения запись снова используется.

Команды: `/add_bd date:ДД.ММ.ГГГГ`, `/remove_bd`, `/my_bd`, `/bd_help`.

- `/next_bd` — 10 ближайших дат, начиная с сегодня, и число дней до них по Москве.
- `/list_bd [month:1–12]` — календарь по месяцам, по 10 записей на страницу.
  Кнопки переключают месяц или страницу, работают 3 минуты и доступны только
  открывшему список пользователю на том же сервере. При нажатии данные читаются
  заново, поэтому удалённые записи исчезают. После истечения срока вызовите команду снова.
- `/preview_bd [user]` — только с правом «Управлять сервером»; показывает точное
  поздравление на ближайшую годовщину с возрастом на эту дату. Ответ приватный,
  без упоминаний-уведомлений, отправки в канал, ветки или изменения журнала доставки.

Календарь и ближайшие даты видны только вызвавшему команду; год рождения там
не показывается. Списки включают сохранённые записи вышедших, о чём сообщает подпись.
Добавление и удаление допускают необязательного участника `user`; менять чужую
запись можно только с Discord-правом «Управлять сервером». Ответы команд приватные.
Несуществующую или будущую дату нельзя добавить командой. Год из исходного
файла сохраняется без догадок и исправлений; возраст рассчитывается по нему.
Импортированные будущие даты сохраняются с приостановкой поздравлений.

Состояние хранится в `automation_settings`, без новых таблиц. Оно не связано
с удалением/архивацией аккаунтов сайта. Один получатель поздравляется один раз за
год, даже если дату отредактировали или бот перезапустился. Перед отправкой есть
транзакционная заявка; при неопределённом результате отправки бот ждёт 10 минут,
затем ищет своё поздравление в истории с первой попытки. Если история недоступна,
повторная отправка блокируется. Сетевые вызовы идут вне транзакции БД.

## Установка

После объединения PR возьмите полный SHA итогового коммита main. Загрузите исходный
`birthdays (1).json` на сервер, например в `/root/birthdays.json`; файл содержит
личные даты, его не нужно добавлять в Git или отправлять в публичный канал.

```bash
bash scripts/update_birthdays.sh ПОЛНЫЙ_SHA /var/www/balance-app /root/birthdays.json
```

Установщик получает код выбранного коммита, сохраняет проверенную копию SQLite и
архив заменяемых файлов в `/root/birthdays-before-*`. Он встраивает регистрацию в
установленный `discord_bot.py`, сохраняя другие функции, устанавливает модуль и
CLI импорта, затем импортирует JSON после проверки точного плана. Совпадающие даты
не дублируются, конфликтующие даты останавливают импорт; прежние записи сохраняются.
Импортированный реестр при откате кода не удаляется, рабочая БД не заменяется.
Перезапускается только `discord-bot.service`. Сайт и сборщики не перезапускаются.
Для обновления кода без повторного импорта третий аргумент можно опустить.

Отдельный импорт в уже установленной версии:

```bash
cd /var/www/balance-app
./venv/bin/python scripts/import_birthdays.py /root/birthdays.json
# Проверьте records/additions/existing/paused, затем вставьте полученный digest:
./venv/bin/python scripts/import_birthdays.py /root/birthdays.json --apply-digest DIGEST
```

Боту нужны просмотр канала, отправка сообщений, встраивание ссылок и чтение истории.
Для реакции и ветки дополнительно нужны добавление реакций, создание публичных
веток и отправка сообщений в ветках. Ошибка декораций не повторяет поздравление.
Токен берётся только из серверного `.env`. Старый отдельный бот-поздравлятор следует
остановить, иначе два независимых бота смогут отправить по одному поздравлению.

Локальные тесты используют вымышленные записи и подмену Discord; рабочие сообщения
не отправляются. Установка и настоящий Discord проверяются владельцем отдельно.

Проверки: общий `bash scripts/check.sh` — 985 passed; 16 тестов дней рождения
проверяют календарь и кнопки, приватный предпросмотр, права команд, перезапуск, неопределённую отправку, импорт
и сохранение других функций при установке. Discord при тестах подменён.

После согласования с `main` (события форума, напоминания, шаблоны, итоги и личный
календарь): `bash scripts/check.sh` — **1024 passed**, 2 предупреждения зависимостей.
Отдельно проверена совместная регистрация команд дней рождения и событий, а также
обоих обработчиков `on_ready`/`on_resumed` без подключения к Discord.
Конфликты разрешены с сохранением обеих подсистем. На сервер это не устанавливалось.

Веб-управление: **Админка → Дни рождения**, доступ всем администраторам по решению
владельца. Добавление/изменение дат, полный список, импорт с точным предпросмотром
и экспорт прежнего JSON используют тот же реестр бота. Установка веб-функций:
`ADMIN_FEATURES_UPDATE.md` (`update_admin_features.sh`); `update_birthdays.sh`
по-прежнему устанавливает только поздравления/команды бота.
