# Го на двоих со ставками и выбором поля

Добавлены лобби `/games/go/lobby` и отдельные сохраняемые столы.
Создатель выбирает 9×9, 13×13 или 19×19, равный взнос в БК и доступ
«Открытый»/«По ссылке». Оба участника подтверждают условия до списания.
Смена размера, ставки или доступа сбрасывает готовность.

## Изученные правила и выбранный вариант

Реализация основана на **китайском подсчёте площади в варианте OGS/KGS**:
позиционное суперко, запрет любого самоубийства, коми белым 7,5, без форы.
Коми 7,5 одинаково на всех трёх размерах и явно показано до старта.
Это определённый онлайн-вариант Го; он не смешивает японский подсчёт территории
с китайским и не выдаёт простое ко за позиционное суперко.

Для сверки прочитаны подробное описание
[правил KataGo](https://lightvector.github.io/KataGo/rules.html), его
[исходный документ](https://github.com/lightvector/KataGo/blob/master/docs/rules.html)
и [параметры китайского варианта OGS/KGS](https://github.com/lightvector/KataGo/blob/master/cpp/game/rules.cpp).
Документ отдельно различает обычный турнирный китайский вариант и OGS/KGS
с позиционным суперко. Выбран второй вариант. Независимая проверка захватов
и площади выполнена с **sgfmill 1.1.1**; она устанавливается только в отдельную
среду разработчика, не является зависимостью сайта. Чужие исходники в движок
не копировались.

### Ходы и захваты

- Играют на пересечениях; чёрные первыми, цвета случайно назначает сервер.
- Соединение и дыхания — только по горизонтали/вертикали, не по диагонали.
- Сначала снимаются группы соперника без дыханий, затем проверяется своя группа.
  Поэтому ход внутрь окружения с захватом может быть законным.
- Самоубийство одного камня или группы запрещено.
- Запрещено повторение **любой** прежней позиции доски, включая начальную.
  История сохраняется после перезапуска и возобновления подсчёта.
- Пас разрешён, не считается запрещённым повторением и не очищает историю ко.
- Нет автоматического ограничения по количеству ходов или таймера хода.

### Два паса и согласование

Два последовательных паса переводят партию в фазу подсчёта. **Выплаты ещё нет.**
Ни один участник не может единолично отметить чужие камни мёртвыми и получить банк.

Нажатие на камень выбирает группу. Кнопка отметки помечает/возвращает всю
связанную группу. Любое изменение отметок сбрасывает оба подтверждения.
Итог фиксируется только после подтверждения одного варианта обоими участниками,
с проверкой актуальной ревизии каждого запроса. Повторное подтверждение отклоняется.

Если спорят о жизни группы, сэки или незавершённых границах, любой участник может
нажать «Продолжить игру». Возвращается исходная доска с сохранённой очередью:
следующим ходит игрок, который был бы следующим после второго паса. Отметки
мёртвых групп и подтверждения очищаются; история суперко остаётся. Спорные
камни можно захватить обычной игрой и снова завершить её двумя пасами.

Автоматического определения жизни/смерти и японских специальных решений вроде
«загнутой четвёрки» нет: выбранный вариант использует согласование и доигрывание.
Неотмеченные группы при согласованном подсчёте считаются живыми.

### Очки

Чёрные: живые камни + окружённые только чёрными пустые пункты.
Белые: живые камни + окружённые только белыми пустые пункты + 7,5 коми.
Пленные показываются отдельно и **не добавляются второй раз** к очкам.

Общие пустые области, граничащие с обоими цветами, нейтральны. В сэки общие
дыхания нейтральны; полностью окружённые одним цветом внутренние пункты
считаются по правилам площади, без японского исключения территории сэки.
Мёртвые камни убираются только из копии для подсчёта. При продолжении партии
они остаются на исходной доске. Очки хранятся целыми полуочками, коми равно 15.
При таком коми ничья по очкам невозможна.

## БК и сохранение

Ставка — равные взносы обоих, 0 БК означает бесплатную партию. При отрицательном
балансе участие недоступно. Перед списанием повторно проверяются оба баланса
и место для возможной выплаты. Допустимый взнос ограничен меньшим балансом
двух участников; посторонние аккаунты не влияют. После старта сумма фиксируется.

Победитель получает банк целиком без комиссии. Кошелёк, две записи финансовой
истории и runtime фиксируются одной общей транзакцией. При ошибке выплаты
завершающее действие и второе подтверждение откатываются вместе с кошельком.
Сдача или выход в игре/подсчёте означает поражение. Активный стол, включая фазу
подсчёта, нельзя расформировать административной кнопкой.

Через 8 часов без успешных действий участников незавершённая партия закрывается,
взносы возвращаются один раз. Опрос страницы и фоновые проверки срок не продлевают.
После завершения можно начать новую партию с новой готовностью и взносом.

Снимок сохраняет ходы, пасы, возобновления, цвета, очередь, взнос, мёртвые
группы и подтверждения. При восстановлении история проигрывается заново,
проверяются захваты, суперко, итоговая доска и согласованный результат.
Пользователь не может прислать свой итог, произвольные очки или победителя.

## Управление

Выберите пересечение и отдельно подтвердите постановку камня. Сам выбор,
отпускание пальца или прокрутка не отправляют ход. На телефоне есть масштаб
100/150/200/300% и прокрутка внутри поля. Подписаны координаты, буква I пропущена.
Стрелки перемещают фокус; Enter выбирает пункт. Пункт последнего хода выделен.
В подсчёте показаны территория, живые камни, коми, нейтральные пункты и отметки.
Разметка поля остаётся стабильной при опросах; имена участников экранируются.

## Проверки разработчика

```bash
. .venv/bin/activate
bash scripts/check.sh
python scripts/check_go_browser.py --app-python .venv/bin/python \
  --chromium /usr/bin/chromium --screenshot-dir /tmp/go-screens
```

Независимая сверка — отдельно от серверных зависимостей:

```bash
python3.12 -m venv /tmp/go-reference
/tmp/go-reference/bin/pip install sgfmill==1.1.1
/tmp/go-reference/bin/python scripts/check_go_reference.py
```

Unit-проверки включают захват групп, дыхания/диагонали, самоубийство,
обычное ко, длинный цикл тройного ко, разрешённый snapback, два глаза,
нейтральные области, подсчёт с коми, взаимное согласие и его сброс,
продолжение спора, восстановление, ошибки выплаты, повторы и CSRF.
Браузер и независимая библиотека работают на синтетических данных без Discord,
рабочей БД, авторизационных обходов и внешних запросов приложения.

## Установка после объединения PR

На сервер самостоятельно ничего не устанавливалось. Нужен полный SHA
итогового коммита `main`, содержащего все согласованные игры. Если перед
этим объединён другой игровой PR, обновите ветку из `main` и дождитесь проверок.
Общий установщик проверяет полноту модулей и сохранение всех уже установленных
ключей runtime: старый коммит не сможет молча удалить другую игру.

```bash
bash <<'BASH'
set -euo pipefail
umask 077
revision=ВСТАВЬТЕ_ПОЛНЫЙ_SHA_ИЗ_MAIN
installer=$(mktemp /tmp/go-install.XXXXXX)
trap 'rm -f "$installer"' EXIT
curl -fL --max-time 60 \
  "https://raw.githubusercontent.com/Kirito63884/ST-9economic-bot/$revision/scripts/update_go.sh" \
  -o "$installer"
bash "$installer" "$revision" /var/www/balance-app
BASH
```

Обёртка запускает общий установщик из того же SHA. Он делает приватную копию
заменяемых файлов и проверенную копию SQLite, проверяет чтение библиотеки шахмат
пользователем `www-data`, импорты, снимки и зависимости шаблонов. При ошибке
возвращает прежние файлы, рабочую БД поверх новых записей не восстанавливает.
Новых таблиц или серверных зависимостей для Го нет.

Обычно перезапускается только сайт. Общий установщик перезапускает бота только
при отличиях перечисленных в нём файлов БД/правил сборов; сборщики не трогает.
`.env`, cookies и секреты не включаются в комплект кода.

После установки: Ctrl+F5 → Игры → Го. Сначала проверьте бесплатную партию
двумя аккаунтами: выбор поля, ход, пас, подсчёт, возобновление и согласование.
Затем можно проверить согласованный небольшой взнос и историю БК.

Фактические результаты локальной проверки: общий набор — **770 passed**, код 0;
проверки движка и HTTP после последней правки — **34 passed**. Независимая сверка
sgfmill — **29 328 попыток хода и 8 031 допустимая позиция**, совпали захваты,
запрет самоубийства и разница площади; суперко дополнительно проверено
целенаправленными позициями, включая тройное ко. Браузерный сценарий двух
сессий прошёл все размеры, мышь/касание, масштабирование, пасы, отметки,
доигрывание спора, два согласия, выплату, рематч и отказ постороннему — без
ошибок JavaScript. Установщик прошёл успешную установку и откат при ошибках
копирования, импорта, HTTP и зависимости; рабочие настройки/данные и сборщики
в фикстуре сохранены. Реальный импорт и рекурсивная проверка шаблонов также
прошли на отдельной временной SQLite с подготовленной схемой.
