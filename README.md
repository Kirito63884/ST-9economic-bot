Сайт на FastAPI и Discord-бот: экономика Bishopcoin, профили участников,
мини-игры, статистика Squad, награды, контроль сборов и административная панель.

Актуальное обновление добавляет предварительный просмотр массовых операций,
индикаторы свежести статистики и защиту запросов. Для всех 16 знаков действует
подтверждение старшим/главным администратором или владельцем; без решения
через 24 часа знак выдаётся автоматически. «Лучший пилот» выдаётся за
первое место завершённой недели в разделе «Пилот» Protocol, «Лучший мехвод» —
за первое место в разделе «Экипаж». Старый критерий знака «Лучший экипаж» сохранён.

# Исправленная версия Balance App

Проект проверен локально на Python 3.12 с SQLite. Сохранены существующие маршруты, настройки Discord-прокси и запуск `main:app` через Gunicorn. Базовое исправление уже установлено на вашем сервере и проверено вами. Дополнительный вход по ссылке подготовлен локально; для него нужно установить новый архив по LOGIN_UPDATE.md.

## Новый вход без Discord в браузере

Игрок получает личную одноразовую ссылку командой `/login` в приложении Discord. Главный администратор также может выдать или отменить ссылку через админку, в том числе для нового участника по Discord ID. Ссылка действует десять минут; новая ссылка отменяет прежнюю. На странице нужно подтвердить вход. Создаётся обычная сессия прежнего профиля: баланс, игры, история, ник, приватность и права сохраняются. Нужная роль проверяется при входе; правила семидневного хранения действуют как раньше.

Секреты ссылок хранятся в базе только как SHA-256-отпечатки. Одновременное использование допускает один успешный вход. Предпросмотр ссылки не выполняет вход. Ссылки сохраняются при перезапуске, а их десятиминутный срок продолжает идти. Выдача чужих ссылок доступна только главному администратору; ручная выдача требует проверки личности получателя.

Для адреса ссылок используется `SITE_URL`, например `https://striketeam9bank.ru`; при отсутствии — origin из `DISCORD_REDIRECT_URI`. Публичный адрес должен использовать HTTPS. Для установки поверх текущей версии см. `LOGIN_UPDATE.md`. Новых библиотек нет.

## Что исправлено

- Устранены две синтаксические ошибки, мешавшие запуску `main.py`.
- Сайт и бот используют общую схему БД; `.env`, шаблоны и относительный SQLite-путь привязаны к каталогу проекта.
- Состояние блэкджека, Crash, покера и заявок сохраняется в `app_runtime`. Баланс, история и состояние игры фиксируются одной транзакцией. Ошибка откатывает и БД, и состояние игры.
- Повторные выплаты и одновременные списания защищены общей блокировкой БД. Проверен одновременный запуск двух независимых процессов.
- При простое приложения более 5 секунд игровые часы сдвигаются на время простоя: текущие раздачи и Crash продолжаются. Срок хранения удалённых аккаунтов при этом идёт по обычным календарным часам.
- Блэкджек: обычная победа — выплата x2; натуральные 21 — x2.5; оба натуральных блэкджека — возврат ставки. Повторный расчёт безопасен. Перезагрузка страницы восстанавливает раздачу.
- Рулетка: зеро выплачивает x36 с учётом ставки. История новых игр содержит чистый результат, а не выплату со включённой ставкой.
- Crash: комиссия 5%; авто-кешаут учитывается даже при задержке опроса; расчёт выполняется и без открытой страницы. Устранены переполнение экспоненты и зависание у границы коэффициента.
- Покер: исправлены блайнды, порядок ходов, завершение улиц, all-in, повторное открытие рейза, побочные банки, возврат неуравненной части ставки и выход из раздачи. Результаты записываются в историю. Карты сбросивших игроков не раскрываются. Одновременно можно участвовать в одном покерном столе. Бонусы и административные изменения не затираются старым балансом стола.
- Ввод NaN, Infinity, отрицательных и чрезмерных значений отклоняется. Ставки задаются с точностью до 0.01. Остаточные центы при разделении покерного банка распределяются после дилера по кругу.
- OAuth использует одноразовый `state` с ограничением срока. Сбой Discord не открывает доступ и не вызывает удаление пользователя. Первый зарегистрировавшийся пользователь больше не получает административные права автоматически.
- При подтверждённой утрате роли/членства игрок скрывается с сайта, его сессия перестаёт давать доступ. Учётная запись, баланс, профиль и история сохраняются 7 дней. Возврат роли восстанавливает аккаунт при входе или фоновой проверке. По истечении срока учётная запись и её история удаляются; следующий вход создаёт новый аккаунт.
- Незавершённые одиночные ставки при удалении аккаунта возвращаются; выход из покера сохраняет расчёт уже вложенных фишек. All-in доигрывается. Проверка ролей работает примерно раз в 5 минут; сетевые ошибки пропускаются.
- Исправлены обход требований к младшим администраторам, повторные ID в массовом начислении, повреждённый JSON и ограничения доступа к заметкам. Массовые изменения и импорт доступны старшим администраторам; младшим для отдельного изменения баланса нужна причина.
- Бот использует общий профиль и уникальность Steam ID. Скрытый профиль защищён в команде просмотра. Для slash-команд убраны ненужные привилегированные intents; ошибки не показывают пользователям внутренние подробности.
- Устранены опасные HTML-вставки имён и чата, неисправная кнопка выхода из покера и неверный расчёт минимального рейза на странице. Из `admin_logs.html` удалены другой HTML-документ и строка терминала.

## Проверки

92 автоматических теста прошли, включая 32 проверки нового входа. В них проверяются выплаты, параллельные ставки, бонусы, повторный расчёт, покерные банки, скрытые профили, архивирование/восстановление аккаунтов, откат транзакций, новая загрузка в отдельном процессе и миграция старой SQLite-схемы без потери баланса. Проверены отрисовка 11 страниц и синтаксис 12 встроенных блоков JavaScript. Статическая проверка Python прошла.

Discord в тестах подменён ответами: реальные токены и соединение с вашим Discord-сервером не проверялись. Ubuntu, Gunicorn и существующий `.env` проверяются после установки на вашем сервере. Старые записи истории не пересчитываются автоматически: в них нет полной исходной информации о ставках.

## Установка на существующий сервер

Первичная установка описана в `UPDATE.md`, обновление с новым входом — в `LOGIN_UPDATE.md`. Нужно загрузить весь архив: кроме `main.py`, появились `database.py` и `runtime.py`, изменён бот и шаблоны. В архиве нет вашей базы, `.env`, токенов или виртуального окружения.

Параметры в существующем `.env` сохраняются. Проверьте, что заданы `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI` с публичным адресом callback и `ADMIN_DISCORD_ID`. Для ограничения по роли нужны `REQUIRED_GUILD_ID`, `REQUIRED_ROLE_ID`, `DISCORD_BOT_TOKEN`. Для HTTPS рекомендуется `COOKIE_HTTPS_ONLY=true`. Если `SECRET_KEY` не указан, постоянный ключ хранится в БД; перезапуск не сбрасывает сессии. В БД хранится приватное состояние игр, поэтому она должна оставаться доступной только серверу и его администратору.

## Примечания к реализации

Для небольшого сообщества выбран общий сериализуемый снимок игр в одной строке БД. Это обеспечивает согласованность с балансом и работу после перезапуска; при большой нагрузке такой способ потребует отдельного проектирования хранения и блокировок.

OAuth `state` следует [официальной рекомендации Discord](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx). Запуск и остановка фоновых задач используют [lifespan FastAPI](https://fastapi.tiangolo.com/advanced/events/).
