# Дни рождения, права Discord и награды за события

## Дни рождения на сайте

**Админка → Дни рождения** доступна всем администраторам, включая младших.
Обычные игроки не получают список, даты рождения или файл через API.

В форме указываются Discord ID человека, имя и дата `ДД.ММ.ГГГГ`. Можно добавлять
новые записи, редактировать прежние, искать по имени/ID/дате. Это тот же реестр,
который используют команды и поздравления Discord: копировать данные между
сайтом и ботом не требуется. Выход из клана записи не удаляет.

Кнопка **«Скачать birthdays.json»** выгружает весь текущий реестр в прежнем формате:

```json
{
  "123456789012345678": {"name": "Пример игрока", "date": "15.06.2000"}
}
```

Для загрузки подходит исходный `birthdays (1).json` (UTF-8, допустим BOM), до
128 КБ. **«Проверить файл»** показывает добавления и изменения; запись в базу
происходит только после **«Подтвердить импорт»**. Повторяющиеся JSON-ключи,
неверные ID/даты и повреждённые файлы отклоняются целиком. Файл объединяется с
реестром: отсутствующие в нём люди сохраняются. Имена и даты совпавших ID меняются
строго по подтверждённому плану. Подтверждение привязано к администратору, файлу
и текущим данным, действует 5 минут и используется один раз. Изменение даты
через Discord между просмотром и подтверждением потребует нового предпросмотра.

Исходные необычные годы, включая 1814, сохраняются. Будущие даты можно перенести
из старого файла с явным предупреждением; бот их пока не поздравляет. При ручном
вводе будущая дата запрещена. Личные записи не включены в Git/установщик.

## Автоматические права сайта

Роли Discord:

- `1458519514470682654` → младший администратор;
- `1447307527846101222` → старший администратор; при обеих ролях старшая приоритетна.

Права применяются при проверенном входе, очередной проверке членства сайта и
полной синхронизации состава. Новые участники появляются через штатную загрузку
состава. Снятие старшей роли оставляет младшие права, если соответствующая роль
есть; снятие обеих убирает только автоматически выданные права. Ошибка Discord
не считается отсутствием роли. Требование членства в клане сохраняется.

Ручные назначения запоминаются отдельно: ручной младший после снятия автоматической
старшей роли снова станет младшим. Ручной старший останется старшим. Уже существующие
права при первой синхронизации считаются ручными. Владелец, техадмины и главные
администраторы не понижаются этой функцией. Если Discord-роль сохраняется, ручное
снятие младших/старших прав не запрещает автоматическую выдачу при следующей проверке:
для прекращения автоматического доступа снимите соответствующую роль Discord.
Изменения отражаются в журнале ролей; Discord-роли бот этим кодом не назначает.

## Бишопкоины за события

**Админка → События → выбрать сохранённое событие → Награды за событие**.
Доступ: старшие/главные администраторы, техадмин и владелец. Младший не может
просматривать получателей/выплаты или начислять через API.

Нажмите **«Загрузить получателей и выплаты»**, найдите игроков, отметьте вручную
и укажите сумму каждому. Можно выбрать любого активного игрока сайта, независимо
от записи в событие. Никто не выбирается автоматически. Допустимо от 0,01 до
1 000 000 БК на человека, до двух знаков после запятой, максимум 1000 получателей.
Предпросмотр показывает точных людей, суммы и общий итог. Деньги добавляются только
после **«Подтвердить начисление»**. Это административная награда, без списания
с баланса организатора.

Каждому человеку можно начислить **одну награду за одно событие**. Остальных можно
наградить следующим подтверждением. Повторы, двойной клик и параллельные запросы
не создают второй выплаты. За отменённое событие начисление запрещено. Если человек
стал недоступен, баланс достиг лимита или событие изменилось, весь план отклоняется.
Баланс, история кошелька, квитанция выплаты и аудит сохраняются одной транзакцией.
Сохранение итогов события само по себе денег не выдаёт. Реальные выплаты в ходе
разработки не выполнялись.

## Установка

Изменения рассчитаны на установленные события форума и текущую систему админки.
После объединения возьмите полный SHA коммита `main`:

```bash
bash scripts/update_admin_features.sh ПОЛНЫЙ_SHA /var/www/balance-app
```

Установщик создаёт проверенную резервную копию SQLite и архив прежних файлов.
Общие файлы `main.py`, `roster_membership.py`, `automation_admin.py`,
`forum_events_admin.py`, `discord_bot.py` и шаблоны дополняются точечными вставками;
неизвестная структура останавливает процесс до замены файлов. Перезапускаются
сайт и бот; сборщики не перезапускаются. Миграций и новых зависимостей нет.
Проверка маршрутов использует OpenAPI и совместима с `_IncludedRouter` FastAPI.
Установщик также подключает существующий модуль поздравлений, если он ещё не
подключён. JSON с датами загружается затем через сайт. Рабочая БД при откате кода
не заменяется. Сохраните путь резервной копии из вывода.
