# Настройки канала «Состав»

В админке добавлена отдельная вкладка **Управление → Канал «Состав»**.
Доступ к редактору и API имеют только старшие и главные администраторы,
а также владелец и технический администратор с существующим полным доступом.
Младшие администраторы и обычные участники не могут читать или менять настройки.

## Что можно менять

- ID каждой из 12 существующих ролей публикации. Числа передаются строками,
  без потери точности больших Discord ID.
- Описания должностей и задачи существующих групп; задачи учебной группы.
- Дополнительные роли: ID, название, описание, значок перед именем,
  вид блока «Должность»/«Группа» и место в первом либо втором сообщении.
- Дополнительную роль можно удалить после проверки нового варианта.

Редактор не выдаёт роли в Discord, не создаёт роли и не меняет права сайта,
фильтры игроков, распределение групп для посещаемости или правила наград.

## Формат сохранён

Остаются два существующих сообщения, прежние заголовки, оформление, разделители,
порядок исходных блоков и распределение командиров/подгрупп/рядового состава.
В неизменённой конфигурации результат побайтно совпадает с прежней реализацией;
это закреплено регрессионной проверкой двух сообщений.

Описания — обычный текст. Для задач укажите одну задачу на строку без начального
маркера: бот сам добавит `•`. Markdown в пользовательском тексте экранируется,
массовые упоминания отключены. В предпросмотре показан точный текст с разметкой
Discord, а не HTML-редактор.

## Как пользоваться

1. Открыть вкладку и развернуть нужную роль.
2. Вставить новый ID роли из Discord или изменить описание.
3. При необходимости нажать «Добавить роль» и заполнить новый блок.
4. Нажать «Предварительный просмотр» и проверить **оба** сообщения.
5. Нажать «Сохранить проверенный вариант».

Изменение любого поля отменяет ранее полученное подтверждение. Сервер проверяет
автора, текущую версию настроек, точный состав формы, снимок участников и срок
предпросмотра 5 минут. Другой администратор не может применить чужое подтверждение,
повторное применение прежней версии отклоняется. Изменения записываются в журнал.

Бот применяет сохранённые настройки при следующем цикле публикации, обычно
не позднее 10 минут; перезапуск после каждого сохранения не нужен. В редакторе
показаны дата снимка Discord и статус применения сохранённой версии.

Новый снимок получает сам существующий бот, вне блокировки БД. Сайт не обращается
к Discord во время записи настроек. При наличии снимка проверяется существование
ID в том же Discord-сервере. Если роль создана только что, дождитесь обновления
снимка. До первого снимка редактор явно показывает предпросмотр без имён;
при публикации бот повторно проверит роли по живому ответу Discord.

Лимит — два сообщения по 2000 UTF-16 единиц Discord. При переполнении состав
не обрезается, третье сообщение не создаётся, прежние сообщения сохраняются.
Нужно сократить описания или другой текст. Отсутствующие роли, неполные данные
и неоднозначные ID сообщений также останавливают публикацию без замены состава.

## Совместимость и установка

Новых таблиц и зависимостей нет: настройки и последний снимок хранятся в
существующей `automation_settings` под отдельными ключами `discord_roster:*`.
`main.py`, игровые модули и runtime не заменяются. Новые маршруты подключаются
через существующий `automation_admin.make_router`.

На сервер автоматически ничего не устанавливалось. После проверки и объединения
PR используйте полный SHA итогового коммита из `main`:

```bash
bash <<'BASH'
set -euo pipefail
umask 077
revision=ВСТАВЬТЕ_ПОЛНЫЙ_SHA_ИЗ_MAIN
installer=$(mktemp /tmp/roster-settings-install.XXXXXX)
trap 'rm -f "$installer"' EXIT
curl -fL --max-time 60 \
  "https://raw.githubusercontent.com/Kirito63884/ST-9economic-bot/$revision/scripts/update_roster_settings.sh" \
  -o "$installer"
bash "$installer" "$revision" /var/www/balance-app
BASH
```

Установщик сохраняет приватный архив заменяемых файлов и согласованную копию
SQLite через backup API с `quick_check`. Затем заменяет только файлы редактора,
публикатора и соответствующий шаблон админки. При ошибке возвращает прежние файлы
и удаляет добавленные. Рабочую БД поверх текущих записей не восстанавливает.

Перезапускаются сайт и Discord-бот. Сборщики SQSTAT/Protocol/онлайна не
перезапускаются; `.env`, секреты, сохранённые игры и балансы не заменяются.
Скрипт проверяет импорты и шаблоны от имени `www-data`, затем HTTP сайта.

После установки: Ctrl+F5, открыть редактор старшим/главным администратором,
проверить предпросмотр без изменений и дождаться очередного цикла бота.

```bash
journalctl -u discord-bot.service --since '5 minutes ago' --no-pager -n 60
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:8000/
```

## Локальные проверки

Общий набор: `bash scripts/check.sh`. Браузер:

```bash
python scripts/check_roster_settings_browser.py --app-python .venv/bin/python \
  --chromium /usr/bin/chromium --screenshot-dir /tmp/roster-settings-screens
```

Runner использует новую временную SQLite, вымышленных участников и сессии;
внешние запросы заблокированы, Discord-публикатор и сборщики не запускаются.
Смена ролей и редактирование настоящих сообщений Discord при проверках не выполнялись.

Фактическая локальная проверка: `bash scripts/check.sh` — **754 passed**,
код завершения 0. Браузерная проверка старшего/главного администратора и отказа
младшему, ID/описания, дополнительной группы, предпросмотра и перезагрузки
сохранённых настроек прошла на компьютере и телефоне без ошибок JavaScript.
Установщик проверен на успех и откат при ошибке копирования, импорта и HTTP;
основной код, игры, `.env`, база и сборщики в фикстуре сохранены. Отдельно прошёл
реальный импорт и рекурсивная проверка зависимостей шаблона на временной SQLite.
